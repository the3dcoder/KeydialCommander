# K20 Recovery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Recover K20 input without stuck owned keys, ghost actions or stale macros.

**Architecture:** Preserve existing layers. The output writer owns key activations; the action engine owns generations and bounded macro tasks; the evdev source owns synchronization and readiness. Binding publication synchronously invalidates those lifecycles through direct callbacks.

**Tech Stack:** Python asyncio/evdev/uinput/aiohttp, pytest, React/TypeScript/Vite.

**Spec:** `docs/superpowers/specs/2026-10-30-k20-recovery-design.md` (approved).

## Global Constraints

- Work only in Commander in the provided feature checkout; preserve Earl-only Git identity.
- No physical capture, running-service/profile changes, system installation or deployment.
- Retain release-triggered peak chords, physical sticky holds and current dial pulses.
- Eight concurrent macro tasks, including previews; no backlog.
- Whole-device neutral rearm; output failure requires restart, not automatic recreation.
- Bluetooth and USB qualification remain separate, unperformed hardware checks.
- Run tests using `/tmp/keycommand-python/bin/python`; exclude hardware capture. Bound commands with shell timeouts. Record executor/socket environment limitations separately.

## Review Focus

- Reset inside a translated pair cannot release or trigger a new-profile action (tasks 2, 4).
- Failed/reused node paths cannot retain dead readers or evict replacements (task 4).
- Partial output acquisition and failed release must report uncertainty and stop output (task 1).
- Silent neutral nodes and fully disconnected previews must not wait for extra gestures (tasks 4, 5).
- Persistence errors and metadata-only edits cannot interrupt a healthy held action (task 3).
