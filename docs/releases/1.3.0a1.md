# Keydial Commander 1.3.0a1 — recovery preview

A Linux preview for configuring the Huion Keydial Mini K20. This release adds
owned-key cleanup, cancellable macros, safer profile changes and recovery that
waits for released controls before accepting fresh input.

Unpack the Linux bundle and open **`INSTALL.md`**. Python is required; **Node and
the source checkout are not required to run the bundle**. The guide covers
Ubuntu prerequisites, user-local installation, initial device access and the
optional desktop window. After setup, open **http://127.0.0.1:8137**.

GitHub's automatic “Source code” downloads are for developers. They need a
frontend build; choose the Linux bundle for the prebuilt UI.

## What changed

- Held actions release their original keys after binding edits or profile
  switches. Overlapping shortcuts preserve another action's held modifiers.
- Macros run without blocking input, with eight concurrent macro slots and no
  backlog. Disconnects, profile changes and shutdown cancel obsolete work.
- Node failures and lost-event frames enter recovery. Already-held controls and
  buffered recovery gestures cannot create fresh actions.
- Aborting a GUI/API macro preview cancels its remaining work.
- Complete action validation occurs before active-map persistence/publication.
- Local status distinguishes connection, readiness and unavailable output.
- Shortcut capture and action drafts support natural editing and explicit Save.

Normal release-triggered buttons, button chords, physical sticky holds and dial
pulses remain the same. Profiles remain YAML under
`~/.config/huion-keydial-mini/profiles/`.

## Qualification and limits

This is a **prerelease**, not a qualified Ubuntu installer release. Bluetooth
has historical K20 evidence from July 2026 on Ubuntu 24.04. Fresh recovery and
USB/data-cable checks remain open. Other distribution builders are unqualified.

The recovery baseline passed **192 Python tests** with hardware capture
excluded and **15 isolated browser regressions**, plus frontend build and lint.
Artifact installation checks are recorded with the release evidence. These
checks do not establish physical transport support.

The published release body records the full commit SHA after the version tag is
created. The evidence record separates wheel installation and isolated API
checks from unperformed hardware, installed-service and clean Ubuntu checks.

Saved dial sensitivity is not yet applied by the input path. Battery reporting,
tray support and automatic application-based profile switching remain roadmap
items. A failed output backend requires resolving the cause and restarting the
user service; desktop receipt of cleanup after such a failure is not guaranteed.
